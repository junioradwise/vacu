# VACU — Virtual Agentic Chrome User

Implement the 26-part Chrome-module inventory from the user's request, in phases with Orca supervised Pi workers. Work exclusively in this developer copy. Do not modify the installed Chrome profile, native-host manifest, app bundle, or the working extension rooted at `~/.local/share/pi-chrome`. Tests use isolated Chrome for Testing with a temporary profile, a fixture HTTP server bound to loopback, and a private temporary socket/home. No real accounts, external browser pages, browser credentials or data in tests. Don't copy ChatGPT extension code; implement behavior independently with documented APIs.

Use Orca's version-matched orchestration guide. Start independent work now, with disjoint files (new per-area modules and scoped tests; no parallel edits to `extension/worker.js`, manifest, CLI, bridge or docs). Coordinator owns integration and public CLI, tests harness and tightened permissions. Establish the adapter contract before dispatch. The worktree is an Orca folder, not a Git checkout. Do not publish, install or lose any previous functionality. Report independently verified results and every remaining gap; no claim of full parity unless verified. Ask before anything that touches the live installation or requires external secrets, an external app account, or a permission-expansion decision.

## Tracks

- **Interaction, 01–05:** visual cursor arrival and click feedback, mouse buttons/modifiers/double-click/drag, both wheel axes, keypress/chords, typing and form controls. Stay origin-bound, verify targets again after visible previews, and do not use frame/coordinate commands to sidestep domain scope. Preserve the existing pointer and keyboard focus behavior.
- **Inspection, 06–11:** typed locators, query/intersection/filter, element metadata, secure iframe scoping, event/deadline waits, full-page/clip/annotated screenshots, dialogs. Support only actually approved frame origins, fail closed on navigation or ambiguity, and preserve fresh refs.
- **Chrome and sessions, 12–18:** back/forward/reload/title/URL/tabs, ownership-aware grouping and moves, windows, session lifecycle/handoff/result markers, Chrome side panel and shortcut, opt-in scoped history/bookmarks, audit and restoration. Never mutate shared/user groups automatically or close user tabs in cleanup.
- **Files and integrations, 19–26:** intentional user-approved downloads, uploads and clipboard; observed assets, explicit exports where site-supported, safe diagnostics (bounded console logs, read-only structured inspection, allowlisted diagnostic CDP only), temporary viewport and show/hide behavior where browser supports it, explicit confirmation/user sign-in handoff, and WebMCP discovery/invocation only where a public API is available. Treat site data as untrusted; no credential retrieval or buffering, no raw arbitrary JavaScript or arbitrary CDP socket, no blanket site/file permissions, no bypassing browser security or ChatGPT-specific auth. Document supported local equivalents and gaps rather than emulating private services. Separate independent submodules if useful.

## Acceptance

1. Existing `vacu` commands and branding still work; Chrome access remains local and domain approval is enforced on all commands, including redirects/frames.
2. Each delivered capability has a concrete CLI/UI entry point, documented permissions/limits, and corresponding isolated validation. Preserve user-private transport and avoid writing secrets or URL credentials into logs/artifacts.
3. Final status maps 01–26 to implemented/partial/blocked with evidence. Avoid claiming the feature is installed in the user's regular Chrome profile. If a track is too large, use dependent tasks and keep the single coordinator responsible for verifying integration.
